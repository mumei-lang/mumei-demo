# Declared summary reuse-attempt routes

Run the optional scenario with a sibling `mumei-agent` checkout:

```bash
make demo-summaries-reuse-attempt
python3 dashboard/cli_report.py reports/summaries_reuse_attempt/latest/result.json
```

The scenario runs each language's existing summary producer, then runs its
matching reuse-attempt route against that manifest. Rust, Solidity and
TypeScript run in-process. The Go helper is built into the scenario output
directory when Go is available; without Go, the helper step and its dependent
Go steps are skipped using the existing optional-toolchain convention.
Manifests and reports are generated by the live routes; no fixture payloads
are used.

| Step | What it does | What it does not do |
| --- | --- | --- |
| `go_reuse_attempt`, `rust_reuse_attempt`, `sol_reuse_attempt`, `ts_reuse_attempt` | Records the versioned reuse-attempt report, observed exit, and selected-result descriptor for each unchanged source/manifest pair | Claim more than attempt lineage or establish language semantics |
| `ts_stale_manifest_refresh` | Changes a copy of `demo_counter.ts` so `add` depends only on `a`, then checks the attempt's stdout digest matches fresh `ts-summaries` output and differs from the unedited run | Carry the stale `[0, 1]` dependency record into the changed source's result |
| `timeout_refusal` | Runs the TypeScript reuse-attempt route with a 1 ms bound and checks that no result is selected | Treat a timed-out attempt as a completed result |

The JSON reports describe bounded attempt lineage. The stale-manifest check
uses byte equality with the fresh producer output for the edited source, which
is the observed output shape for this route.
