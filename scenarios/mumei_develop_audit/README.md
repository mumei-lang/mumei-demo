# Mumei Develop Checkout Audit

This scenario audits a file from the sibling `mumei` checkout pinned to
`develop`. It demonstrates the no-`.mm` entry path for code that already lives in
`mumei`:

1. inventory the develop-checkout target file;
2. run `audit` in live mode, or emit deterministic fixture audit evidence in CI;
3. require `verification_violations` and `cross_validation_gaps`;
4. run `migrate-suggest` so the audit can later become `.mm` guidance.

## Target

`scripts/generate_stdlib_metrics.py` is the audited target. The fixture models a
guardrail gap around stdlib metrics generation: report artifacts are only trusted
after the scenario records an explicit target inventory and generated evidence.

## Run

```bash
make demo-mumei-develop-audit
```

Fixture mode is the default and does not require `OPENAI_API_KEY`:

```bash
CI_FIXTURE_MODE=1 ./scripts/run_scenario.sh mumei_develop_audit \
  --mumei-repo ../mumei \
  --mumei-agent-repo ../mumei-agent
```

Live mode runs `mumei-agent audit` against the develop checkout target. It should
only be used after an API key is explicitly provided for that run:

```bash
CI_FIXTURE_MODE=0 OPENAI_API_KEY=... ./scripts/run_scenario.sh mumei_develop_audit \
  --mumei-repo ../mumei \
  --mumei-agent-repo ../mumei-agent
```

The live command exports `LLM_API_KEY` from `OPENAI_API_KEY` when needed. Fixture
mode never reads either variable.

## Expected output

- `l1_inventory/record_targets: PASS`
- `target_files.json` records `expected_ref: develop` and
  `scripts/generate_stdlib_metrics.py`
- `l2_audit/audit_develop_target: PASS`
- `audit/mumei_develop_audit.json` records:
  - `verification_violations`
  - `cross_validation_gaps`
  - `spec_health_issues`
  - `migration_hints`
  - `openai_api_key_used: false` in fixture mode
- `l3_migrate/generate_migration_guidance: PASS`
- `mm/scan_std.mm` and `mm/render_markdown.mm` are generated by
  `migrate-suggest`

Generated reports live under `reports/mumei_develop_audit/latest/` and include
`result.json`, `report.md`, `harness_state.json`, command logs, the audit JSON,
and generated `.mm` skeletons.
