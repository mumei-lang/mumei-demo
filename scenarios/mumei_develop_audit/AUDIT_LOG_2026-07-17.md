## Landed fixes since 2026-06-21

1. `mumei` — `scripts/generate_stdlib_metrics.py` now exposes two contract-facing
   public wrappers whose names match the spec vocabulary the audit extracts:
   - `analyze_metrics(std_dir, mumei_bin=None) -> list[dict]` wraps `_scan_std`
     (responsibility: std-module metrics collection).
   - `generate_markdown_report(rows, history=None) -> str` wraps `_render_markdown`
     (responsibility: markdown report generation from metric rows).
   - `main()` routes through the new public functions.
2. `mumei-agent` — the cross-validation Z3 lowering
   (`agent/cross_validation_z3.py`) was extended so the two `spec_health_issues`
   (encoding-gap) clauses are no longer false positives:
   - String suffix / path predicates (`directory_path.endsWith('/std/')`,
     `startsWith`, `contains`/`includes`) lower via the Z3 string theory
     (`SuffixOf` / `PrefixOf` / `Contains`). Because mumei's own lowering has no
     string theory, `_mumei_safe_clause` still drops these before emitting a
     `.mm` module so they cannot resurface as a hard mumei lowering failure.
   - Boolean-literal comparisons (`result == true`, `result != false`, and the
     capitalized Python `True`/`False`) lower as boolean equality instead of an
     integer comparison against a fabricated `true` symbol. Foreign contract
     inference (`agent/cross_validation_foreign.py`) now emits mumei's canonical
     lowercase `true`/`false` for bool-returning functions.

## Conclusion — quality-gate observations

These two points from the 2026-06-21 log are operational guidance, not code
fixes, and are restated here (and in the scenario `README.md`) as the standing
conclusion of this audit line:

- **Observation 3 — drift/health findings dominate.** The actionable signal from
  this audit was `spec_health` and `cross_validation` drift, not direct Z3
  counterexamples (`verification_violations` / `counterexample_values` were
  empty of concrete counterexamples in both runs). Treat **spec health and
  cross-validation drift as first-class quality gates**, not just Z3
  postcondition refutations.
- **Observation 4 — a PASSing scenario is not "nothing to fix".** The scenario
  reached `PASS` on 2026-06-21 while the underlying target still had two
  cross_validation gaps and two encoding-gap spec-health issues. **Scenario PASS
  ≠ audited target is clean**: a green scenario pins the contract/report shape
  for CI and the dashboard, but follow-up on the recorded `cross_validation_gaps`
  / `spec_health_issues` is still required.
